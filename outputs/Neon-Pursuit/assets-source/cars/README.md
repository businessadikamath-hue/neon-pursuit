# Original v9 vehicle surface refinement

These files are the original asset sources for a bounded v9 car improvement. The installed v8 game and its sources remain untouched. No manufacturer CAD, scanned vehicle, brand badge, licensed game model, downloaded texture or photograph was used. Real car names remain reference labels; the geometry is an original approximation.

`build_vehicle_bodies.py` runs in Blender 4.5.5 LTS and exports all eight player and twelve traffic body meshes directly to `../engine-v9/blenderVehicleBodiesV8.js`. The retained module filename is an integration contract; its asset contents are v9. `body-designs.json` is the original cross-section input. `neon-pursuit-vehicles-v9.blend` contains the editable modeled bodies, wheels-arch/intake/fascia recesses and preview materials.

The cross-section refinement uses shape-preserving cubic Hermite interpolation with continuous tangents. It keeps 48 samples per ring, preserves each control-point envelope, and avoids overshoot along the sill. Existing Boolean arch and intake recesses, beveled edges, split boundaries, weighted normals and UV unwrap remain. Quantized embedded geometry requires no runtime fetches.

`../engine-v9/vehicleCanopyV9.js` builds fitted glazing and roof/pillar surface patches with shared boundaries. Body panel seams are thinner, the decorative hood rods are removed, and sports-car arch hoops are removed because their wheel arches are already cut into the Blender bodies. Rally and safari retain thinner functional arch trim. Paint and tire normals are more subtle, trim is less metallic, alloy/brake materials are rougher, and lamp emission is tone mapped. No physics values, model IDs, collision dimensions, wheel animation groups, police flash arrays or ownership/disposal contracts changed.

The five embedded Ultra+ parts in `heroVehicleParts.js` are unchanged from verified v8. `build_hero_details.py` and `neon-ultraplus-parts.blend` are copied original sources for these retained assets; only the generator export path is rebased to v9. The planar rotor normal correction remains. Ultra+ detail still uses `userData.setVehicleQuality(name)` and `userData.vehicleDetailTier`; it never automatically reduces detail.

`render-body-proof.py` renders the actual exported v9 black body in Cycles using original area lights. `blender-v9-body-proof.png` is a component render, not a full in-game car or a photograph. The complete runtime assemblies, including glass, wheels and lamps, are shown in `gallery/`.

`gallery/main.js` imports both installed v8 sources and v9 sources into the same fixture. Before/after renders use identical renderer, environment, lights, camera, viewport, quality and pose. `gallery-capture.cjs` captures all eight players and twelve traffic types from front/rear, matched close and far views, and v9 batching comparisons. `compare-pixels.py` checks batching against normalized mean difference <= 0.005 and fraction of pixels with any channel difference > 2/255 <= 0.005. Intended v8-to-v9 art changes are evaluated visually, separately from the batching fidelity limit.

Validation scripts check all 20 models, 40 batching/tier combinations, finite attributes, outward tire normals, planar rotor normals, exact lower-tier visibility/material restoration, lazy reuse, wheel parenting, reachable disposal, and unchanged collision envelopes. The construction timings in the model report are CPU construction observations, not frame rate measurements or claimed speedups. Full-game performance and installation acceptance belong to the main v9 integration task.

Limits: these are still procedural vehicle approximations, with simplified bumper/lamp assemblies and interiors, no manufacturer-exact panels, scanned surface detail or photo-based material capture. A browser renderer with this asset library does not achieve photographic or Forza-level fidelity. This pass targets specific visible surface and overlay defects; it does not claim that broader gap is closed.
